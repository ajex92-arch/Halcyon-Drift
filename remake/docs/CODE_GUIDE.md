# A guide to the code (start here)

This is a map of the whole game's code for someone who has never seen it. Read docs/CODE_STYLE.md for how the code is written, and the header of any file (its WHAT THIS IS / HOW IT WORKS / WHO USES IT block) for the detail.

## What the game is

Halcyon Drift is a space battle for two teams, Aurelian (amber) and Cinder (red). Each team has a huge mothership at one end of the map, an admiral who spends the team's money and gives orders, and 12 pilots who fly ships. Small robot ships called minions fly down three lanes in waves. Ore fields along the lanes can hold turrets. Between the lanes is an asteroid "jungle" with neutral monster ships. You can only see what your team's units can see (the fog of war), and asteroids block sight. The match ends only when a mothership is destroyed. A human takes one seat (admiral or pilot); the computer plays every other seat.

**Team names.** Team 0 is called Aurelian in all player-facing text; code, logs, JSON and tools keep the internal label Halcyon. Rules.TEAM_DISPLAY holds the names the player sees; Rules.TEAM_NAMES holds the internal labels that logs, JSON, tools and node names keep (with Rules.HALCYON, the Halcyon lines in test output and the halcyon_win_rate key). Text that was built from an internal label, such as the place names "Halcyon Top", "Halcyon Mid" and "Halcyon Bottom" or the match-over reason, goes through Rules.display_label() on its way to the screen; the same text in logs and JSON is left alone. Cinder keeps its name.

## The folders

| Folder | What is in it |
|---|---|
| `scripts/world` | the running match (World), the map, asteroids, shots, damage, vision, the directors that send waves and spawn jungle camps |
| `scripts/entities` | every kind of unit: ships, minions, drones, turrets, repair bays, wards, the mothership, monsters; plus guns, shields and energy |
| `scripts/ai` | the computer pilots (pilot_*.gd) and the computer admiral (admiral_*.gd) |
| `scripts/control` | the controls: the human's keyboard/mouse, the ships' "sticks and buttons", and the admiral's order desk |
| `scripts/team` | each team's state (money, research, sieges, drones) and each pilot's record (credits, gear, kills) |
| `scripts/data` | the numbers: ships, weapons, research, items, minions, map layout, rules, colours |
| `scripts/core` | small helpers used everywhere: maths, the spatial hash, steering, the route graph, a seeded random generator |
| `scripts/ui` | everything on screen: the HUD, minimap, hangar, admiral board, help, scoreboard, start and end screens |
| `scripts/autoload` | two always-there helpers: Game (options) and Events (the message board) |
| `scripts/audio, scripts/camera` | sound effects made in code, and the camera |
| `scenes` | Godot scene files that tie scripts to nodes |
| `tests` | test scripts run with --test=<name> (see the tests section) |
| `docs` | the design, the progress log, the user's requirements, this guide, the style guide, the fun plan |

## One tick, step by step

The game moves forward in small steps called ticks, 60 every game second. World._physics_process() runs one tick in a fixed order (changing the order changes the game):

1. the clock moves on, and the directors run (minion waves, jungle camps);
1. the spatial hashes are refilled (grids that quickly answer "who is near here?");
1. vision updates one team's fog of war (each team 5 times a second), and support auras run;
1. every unit takes its turn (sim_update): AI brains think and steer, ships fly, guns fire;
1. units that overlap are pushed apart;
1. every shot in flight moves and hits what it touches (Projectiles);
1. last: resource nodes, the match rules (respawns, the win), the economy, docked AI pilots and the AI admirals.

## The big pieces, area by area

### The match: World and its directors

World (scripts/world/world.gd) is the running match. It keeps the shared state that many files read: the match clock, phase and winner, the systems (map, vision, projectiles, combat, effects, rules, directors, admiral desk, AI brains) and the unit lists (units, ships, minions, turrets, bays, wards, drones, monsters, plus two spatial hashes). It also runs the fixed tick order in _physics_process: clock and directors, then hash rebuild, vision and support, units, separation, projectiles, and last nodes, rules, economy, docked AI pilots and AI admirals. The real work sits in parts next to it, and World keeps thin forwarding functions with the old names so the rest of the game still calls World.launch(), World.spawn_minion(), World.nearest_enemy() and so on. WorldSetup.build() builds a match once. WorldRegistry gives out unit ids, files new units into the lists (attach and index), takes dead ones out (which also starts a pilot's respawn) and refills the spatial hashes each tick. WorldSpawner makes every new unit through the registry, and WorldHangar launches, docks, hyperspace-launches and module-swaps pilots. WorldQueries answers read-only questions (nearest enemy, best bay, place names). WorldMining (static) picks ore nodes for drones and their drop-off point, and WorldResearch (static) upgrades units already in space. WorldVisibility runs the fog of war, WorldSupport runs the support-corvette auras and paint, and WorldSeparation shoves overlapping ships and minions apart. Three "director" objects sit beside it. MatchRules is the referee: it handles respawn timers, hyperspace spool countdowns, the respawn stipend and strain, and the win when a mothership dies. MinionDirector queues and launches the free minion waves and runs Fleet Command buying and orders. JungleDirector spawns jungle derelict camps and respawns them on a timer.

### The map and small helpers

The map is made once, at the start of a match, by MapBuilder (scripts/world/map_builder.gd). WorldSetup calls MapBuilder.build(). MapBuilder holds the shared lists (corridors, keep-out circles, gates, candidate rocks), all the tuning numbers, and the fixed order of the steps. Most steps live in their own "part" file. Each part is made, run once and thrown away:
1. MapBuilder copies the bases, lanes and connector from MapLayout itself.
2. MapBuilderNodes places the ore nodes with their turret slots and ore rocks.
3. MapBuilderJungle places the camps, entrances, gates and winding jungle paths.
4. MapBuilderWalls lays the lane wall rocks and the gate rock pairs.
5. MapBuilderFill scatters the filler rocks.
6. MapBuilder copies every rock, plus its mirror copy, into the map.
7. MapBuilderRoute builds the road map.

Everything is made on Aurelian's (left) half and mirrored onto Cinder's half. The random numbers come from one Mulberry (scripts/core/mulberry.gd). Mulberry is a seeded random number maker that always gives the same sequence for the same seed, so the steps must keep their order.

The result is a MapInfo (scripts/world/map_info.gd), kept as World.map. It is plain data: lanes, nodes, camps, jungle paths, entrances, rock lists, mothership spots and the RouteGraph. It also answers lane_for() and in_open_lane(); the second uses a 200-unit lookup grid.

AsteroidField (scripts/world/asteroid_field.gd, the World scene's "Asteroids" node) turns MapInfo's rock lists into real rocks. Each rock gets parallel data lists, a static physics circle and an hp pool; rocks can be damaged and destroyed, and a rock_destroyed signal goes to Vision. AsteroidFieldQueries keeps a 400-unit grid of rocks and answers nearby(), segment_hit(), segment_blocked() and blocked(); AsteroidField forwards those calls to it. AsteroidFieldChunk draws the rocks in 4,000-unit patches, so a destroyed rock only redraws its own patch. MapDecor draws the starfield, lane bands, base rings and labels under everything.

RouteGraph (scripts/core/route_graph.gd) is the road map of dots and links. path() finds the nearest usable dot at each end, runs a cached A* search between them, and returns [from, ...dots..., to]. Jungle dots are small-ships-only. RouteGraphHeap is the search's priority queue.

The other core files are small shared tools:
- Util is a static library for angles, aiming, segment/circle tests, polylines and money/clock text.
- SpatialHash is a 320-unit grid that is refilled every tick to find units near a point. World.unit_hash and World.big_hash are SpatialHashes.
- Steer has seek, avoid_rocks and advance for light units that don't use the full flight model.
- StatBlock adds up gear and module bonuses by name.

### Ships and the unit family

Unit (unit.gd) is the base class of everything that can fight or be destroyed. It holds the shared state (uid, team, kind, size class, hull, shields, vision, the visible/seen bitmasks, the damage log and aggro memory) and the damage path that Combat calls: take_hit() sends a hit to the shield zone facing the attacker, then to the hull. A hit is described by a DamageInfo (damage_info.gd), a small note with the amount, the weapon kind, who fired and where from. Shields are a ShieldZones (shield_zones.gd): four zones (front, rear, left, right) whose shares follow the focus setting, or one shared pool for minions, turrets, bays and the mothership. A pilot ship's battery and energy routing is an EnergyPool (energy_pool.gd). Every gun on every unit is a WeaponMount (weapon_mount.gd): FIXED, TURRET or AUTO; it aims, waits for its cooldown, pays energy and fires rounds or beams. AUTO mounts choose their targets with WeaponMountTargeting (weapon_mount_targeting.gd), a static library that picks the best enemy or torpedo and works out the lead point. The pilot ship, Ship (ship.gd), extends Unit and keeps all of its own variables and public functions plus the per-tick order (controller, timers, button presses, stats, flight, battery, shields, guns, escort drones). Ship hands the detail to three static-library parts that receive the ship: ShipStats (ship_stats.gd) works out speed, turning, boost, damage, reach, hull, shields, battery and vision from the hull data, gear, modules, team tech, routing and buffs; ShipFlight (ship_flight.gd) is the Newtonian-lite flight model (turning, thrust, boost, speed cap, flight assist) and the move_and_slide crash handling; ShipAbilities (ship_abilities.gd) runs each hull's special ability, repair kits and the Logistics ship's escort drones. Drawing is separate and changes nothing in the game: ShipVisual (ship_visual.gd) paints pilot ships (silhouette, shield arcs, velocity arrow, bars, name, engine flames), and UnitVisual (unit_visual.gd) paints every other kind of unit, with one drawing function per kind.

### Every other kind of unit

The entity scripts in scripts/entities are the things that live in the match. Most of them "extend Unit", so they get hull, shields, team and damage handling for free, and World calls each one's sim_update() once per tick. Minion (minion.gd) is a lane minion. It keeps its state and its per-tick loop, and leans on two static helper libraries: MinionTargeting (minion_targeting.gd) decides who it shoots (it keeps its target until something scores 600 better), and MinionFlight (minion_flight.gd) decides how it flies, either fighting or walking down the lane. Mothership (mothership.gd) is each team's home ship. It keeps its state and its public face: hull_dist, hit_t, dock_radius, launch_point, available, can_move, order_move and apply_upgrades. The actual work is done by four static libraries. MothershipHull handles the long capsule shape: distance to the hull and hit tests. MothershipDrive handles movement after 20:00. MothershipRetreat runs the once-per-match systems failure. MothershipGuns adds the base guns and the research guns, applies hull and shield research, and fires every tick. The other entities are each one file. Turret is the admiral's gun tower on an ore-node slot: it builds up, picks targets with the "aggro" rule and ramps its damage. MiningDrone flies ore between ResourceNodes and the mothership with an out/mine/home/idle state machine, and Economy pays out only when the ore is delivered. RepairDrone is a small healer that works for a RepairBay, a Logistics corvette or a repair kit. RepairBay flies to a spot, anchors there and keeps its drones out. Ward is a stealthy vision drone that parks at a spot. Derelict is a neutral jungle-monster camp, and SnubFighter is the small fighter a Derelict Carrier launches. ResourceNode is the exception: it is not a Unit but a Node2D, an indestructible ore field with turret slots and an ownership ring. World calls its tick(), and turrets, drones, the admiral and the UI all read it. Every entity is created through World.spawn_* -> WorldSpawner, which calls its setup(), except the motherships and ore nodes, which WorldSetup makes. Combat.kill() calls on_killed() when an entity dies.

### Shots, damage and the fog of war

Five owned files, now eleven, cover how damage reaches units and what the screen shows of it. Projectiles (projectiles.gd) is the pool of every bullet, torpedo, shell and flak pellet in flight. Each round is a slot number, and its facts live in parallel lists (pos, vel, dmg, team...). Only this file writes those lists. Each tick, World calls Projectiles.tick(), which moves each live round along a line and handles what it hits. Three parts do the side jobs. ProjectilesHitScan finds the first enemy unit or mothership on a round's line. ProjectilesImpact turns a hit or a timeout into damage, sparks and flak bursts. ProjectilesDraw paints the rounds and beam lines. All damage then flows into Combat (combat.gd), the single damage pipeline. Its apply_damage() asks CombatScaling for the final number after every damage rule, lets the target's shields and hull soak it, keeps the books (assists, the pilot's damage total, turret aggro, sound cue) and calls kill() when the hull reaches 0. kill() pays the rewards, fires the events and removes the unit. Beams (lances, ion) and blasts (flak) find their victims in CombatBeamArea, which hands each hit back to apply_damage(). Vision (vision.gd) is the fog of war: a 200-unit grid with asteroid-blocked cells. Each team's lit cells use a stamp counter, and Scout Ping reveals light a circle that ignores rocks. Its part VisionRays casts the sight rays and caches the results. WorldVisibility calls Vision.update_team() and decides which units are seen. FogView (fog_view.gd) turns the viewing team's lit and explored cells into a one-pixel-per-cell picture stretched over the map. Effects (effects.gd) draws particles and rings. It is visual only and has its own random numbers, so it never changes the match.

### Teams, money and pilot records

The scripts/team folder holds everything that belongs to a whole side or to one pilot, not to a single ship. TeamState (team_state.gd) is one team's shared notebook: the treasury, the tech tree state (facilities, finished research, the build and research queues), every upgrade field that research fills in, the admiral seat, the rally waypoint, the siege and defend fields, respawn strain, the mining-drone queue and loss log, and end-screen stats. All those fields stay on TeamState because many files read them directly. World makes two TeamStates (WorldSetup) and calls TeamState.tick() every tick. tick() runs five small "part" objects in a fixed order. TeamDefense (team_defense.gd) checks once a second for an enemy big-ship push at our mothership (a closer one, 4,000 from the hull, while our mothership is parked up a lane, and only one right at the hull while our own siege is on); TeamStrain (team_strain.gd) counts down respawn strain; then, while our mothership is alive, the treasury gets its income, TeamTech (team_tech.gd) moves the facility and research queues on and turns finished research into upgrades, and TeamDrones (team_drones.gd) builds free and ordered mining drones. TeamSiege (team_siege.gd) has no tick. It only answers where the siege staging and assault points are on a lane. Each part keeps a weak link back to its TeamState, so the two can be freed when a match ends. TeamState keeps thin forwarding functions with the old names (queue_facility, siege_stage_point, defending, note_respawn, drone_danger ...), so callers did not change. PilotProfile (pilot_profile.gd) is one pilot's record for the whole match: credits, the 6 gear slots, the next hull and modules, the pilot's state (docked, spooling, flying or dead) and their scores. Its buying and selling rules live in the part PilotProfileShop (pilot_profile_shop.gd), and PilotProfile forwards its shop functions there. Economy (economy.gd) is a static pay office. It splits delivered ore between the treasury and the pilots, pays the passive trickle, and pays bounties and assists when something is destroyed, using each victim's damage log to find who helped.

### The computer pilots

The computer pilots live in scripts/ai/pilot_ai.gd (PilotAI), one brain per AI seat. It flies the same ships under the same rules as a human: all it does is work the ship's ShipControls, the way a human's keyboard and mouse do. Docked, update_docked() shops about once a second and launches (or, with the Hyperspace Module, jumps to the repair bay nearest its lane front when that saves enough flying). Flying, update() runs every tick: about 3 to 4 times a second it thinks (_think: hull check, shopping trip?, turret aggro, outnumbered?, then the job for its state), and every tick PilotCombat works the controls. Its state is lane (hold a station behind our minion wave; push turrets our minions are tanking; hunt fair-odds prey), jungle (clear derelict camps), retreat (low hull, or for a ship smaller than a frigate low hull plus shields: kit, repair bay or home) or home (fly home to shop). Its temperament, picked by seat, decides what it buys. The brain keeps the shared memory (state, target, goal, timers) and the order of thinking; its parts do the detail: PilotShopping (pilot_shopping.gd: what to buy and when to fly home), PilotGoals (pilot_goals.gd: where to fly in each state, sieges and defending), PilotTargeting (pilot_targeting.gd: what to shoot; a target with a rock in the line scores worse, the pilot being shot stays preferred, and a bomber in the lane leaves small craft alone), PilotSenses (pilot_senses.gd: odds, turrets, nearby minions), PilotCombat (pilot_combat.gd: every tick, fight the target or fly; a ship whose first gun is a beam aims all its turrets straight at the target, so the battlecruiser's heavy cannon fires without lead; a fixed main gun fires only nose-on, the lance overloads while its beam is on), PilotFlight (pilot_flight.gd: fly to a point along the route graph without crashing, unstick, dodge rocks, slide along a mothership hull instead of pinning against it, tell whether a rock hides the target; its own part PilotEscape, pilot_escape.gd, plans a way out when a ship is wedged in a rock pocket) and PilotSystems (pilot_systems.gd: energy routing and shield facing). The parts reach the brain through a weak link (so the two can be freed), and each function looks the brain up once into a local called `brain`.

### The admiral and the controls

The admiral is the team member who doesn't fly a ship. They spend the team's shared money and give the big orders. Two files hold the rules and the computer player for that job. scripts/control/admiral_command.gd (AdmiralCommand) is the rule book: every admiral order (build a drone, a facility, research, a turret, a repair bay, a ward, set the waypoint, move the mothership, buy or order minions) checks the rules, pays and acts. It returns "" or a reason for the player, and sends Events.admiral_result so the HUD can show a toast. The human's AdmiralBoard and CommandOverlay and the computer admiral all go through it, so both play by the same rules. scripts/ai/admiral_ai.gd (AdmiralAI) is the computer admiral. World makes one per AI-run team and calls tick() every physics frame. It thinks once a second and runs a fixed to-do list in order: drones first, a first PD turret at each inner node, the next step of the tech plan, spare-money spending, the waypoint, sieges, moving the mothership, and Fleet Command. It keeps the timers and the order; its parts in scripts/ai/ do the work. AdmiralPlan (admiral_plan.gd) is a static library holding the build order and picking the next step. AdmiralLanes (admiral_lanes.gd) answers map questions (push lane, picked by how far down its own lane our wave is as a fraction, how far our wave is, points along a lane, fleet strength) and is shared by the other parts. AdmiralBuilder (admiral_builder.gd) picks where turrets, repair bays and wards go. AdmiralWaypoint (admiral_waypoint.gd) places the rally marker. AdmiralSiege (admiral_siege.gd) runs the late-game attack on the enemy mothership (gather, then assault, call-off, cooldown; it besieges the lane the enemy mothership is parked on). AdmiralMothershipMover (admiral_mothership_mover.gd) moves our mothership after 20:00, always up the mid lane. AdmiralFleetCommand (admiral_fleet_command.gd) buys minions when the team owns Fleet Command. The parts get the world, the team number and the shared AdmiralLanes helper instead of a link back to AdmiralAI, so no objects leak when a match ends. The pilot side is separate. scripts/control/ship_controls.gd (ShipControls) is the "control sticks" form each Ship owns: aim point, face point, thrust, strafe, boost, fire, plus one-tick requests (special, shield focus, energy routing, repair kit, dock) that the ship clears after reading. scripts/control/player_controller.gd (PlayerController) fills that form from the human's keyboard and mouse every tick. PilotAI fills the same form for bots, so humans and bots fly by identical rules.

### The data tables

scripts/data/ holds the game's tuning tables. These files only describe things; they never do anything on their own. Each one is a class made only of constants (fixed values) plus a few tiny static helper functions, so other code reads them as Rules.X, Ships.HULLS[id] and so on, without creating an object. rules.gd is the shared rule book: team numbers, size classes, weapon kinds, the damage table (DAMAGE[weapon kind][target size class], where each cell multiplies a hit's raw damage: 1.0 normal, 0.5 half, 2.0 double, 0 none), and the special damage rules for motherships, turrets and minions. It also holds shield focus and energy-routing settings, crash damage, all the money numbers, ace streaks, respawn and strain, the admiral's waypoint, vision, and the DESIGN.md variant switches. ships.gd lists the pilot hulls with their price, defence, battery, flight, guns and special ability. weapons.gd lists every gun and beam, and the hulls, minions, turrets, monsters and the mothership name those weapon ids. items.gd (pilot gear plus the repair kit) and modules.gd (ship add-ons, with prices that scale by size) share one set of stat keys, and StatBlock adds those up. tech.gd is the Homeworld-2-style tech tree: mothership facilities, research items, their effects, and the rules for whether something can be queued and whether a hull is unlocked. TeamState/TeamTech run the queues. minions.gd covers lane minion types, wave makeup and timing, and growth over the match. jungle.gd covers the derelict monster camps and snub fighters. turret_data.gd covers admiral-built turrets and the backdoor, aggro, ramp and rebuild-lock rules. structures.gd covers repair bays, repair and kit drones, wards, mining drones and the mothership. map_layout.gd is the hand-made map plan for Aurelian's half, which MapBuilder mirrors for Cinder: lanes, ore nodes, camps, jungle entrances and chokes. palette.gd holds every colour, plus team()/bolt()/with_alpha(). roster.gd holds the pilots' callsigns. The usual flow: entity scripts (Ship, Minion, Turret, Derelict, RepairBay, MiningDrone, Mothership, WeaponMount, Projectiles) read their entries when they are made or when they fire. CombatScaling and Economy apply the Rules numbers. The hangar, admiral board and HUD show labels, blurbs and prices from these tables.

### The screens: HUD and its widgets

The in-match screen is run by Hud (scripts/ui/hud.gd), the "Hud" node in scenes/ui/hud.tscn. The scene holds the whole HUD layout: the widgets are child scenes, placed and anchored in the scene, in the order they are drawn (later ones on top). HudTopBar (hud_top_bar.tscn) is the clock, next wave, mothership hull bars and turret counts. HudMePanel shows your credits or treasury, K/D/A and the earnings log. HudFeed is the kill and event feed; it also remembers how you last died. HudBanner shows the big centre message, HudToast the short pop-up hints, the ShipStatus readout and the Minimap sit at the bottom, and HudSlots shows the gear slots (each a small hud_gear_slot.tscn) and the key reminder. Each widget script reaches its own nodes with @onready and only fills in what changes while playing. main.gd calls Hud.setup(world), which only wires things up: the command overlay, the two helper parts, the world links, and the Events signals, each connected straight to the widget that shows it. Every 0.1 s, Hud._refresh() tells each widget to refresh. Two helper parts (RefCounted) do the screen-manager jobs. HudPanels makes the Hangar, AdmiralBoard, Scoreboard and HelpPanel from their scenes the first time they are needed and keeps only one open. HudInput routes the menu keys: P, Tab, B, H, Esc, C and F. Hud keeps its public face so tests/ui_tour.gd still works: hud.hangar, hud.board, hud.overlay, toast(), _on_match_over() and thin forwarders _toggle_help(), _show_scoreboard(), _toggle_board(), _open_hangar(), _close_others() and _any_panel_open(). CommandOverlay is the Admiral's map tools (arm, apply, box-select, minion orders). It lives under World and gets the clicks the GUI didn't take. Its drawing lives in the static library CommandOverlayDraw (waypoint, bay ranges, selection, tool preview). EndScreen appears when the match ends and StartScreen is the seat choice; both are scenes too, like HelpPanel and Scoreboard. CardButton is the clickable card used by Hangar and AdmiralBoard; it is built in code, because cards are made one per item from game data. UiKit builds the theme from Palette, including the named looks that scene nodes pick with theme_type_variation (MistText, AmberText, PrimaryButton and the boxes TopBarLook, MeLook, ToastLook, SlotLook, BoardLook, HangarLook, HelpLook, ScoreLook, SeatLook, StartLook, EndLook), so no colour is ever written in a scene file. It also keeps one-line builders for the labels, buttons, bars and boxes that are still made in code (rows and cards made from game data). The minimap, the ship readout and the command overlay draw themselves, so they stay code.

### The screens: Admiral board and hangar

The two big command screens now each have a small "shell" script plus one static library per tab. AdmiralBoard (scripts/ui/admiral_board.gd) is the Admiral's Tab panel: its frame (title, status line, away warning, tab buttons, scroll area, details line) is the scene scenes/ui/admiral_board.tscn, and the script switches tabs (_set_tab), refreshes 4 times a second (_refresh), and keeps the shared helpers every tab uses (_ts, _ok, _hover, _inner_w, _grid, _arm, _view). Each tab's cards are built and refreshed by its own library: AdmiralBoardResearch (module grid + the 8 research columns; it also owns tech_card() and progress_text(), which the Mothership and Fleet tabs reuse), AdmiralBoardBuild (drones, turrets per resource node, repair bays, wards), AdmiralBoardMothership (status block, move button, Flagship research cards) and AdmiralBoardFleet (rally waypoint, Fleet Command buy grid and minion orders). The Pilots tab is just an embedded Scoreboard, made from its scene. All purchases still go through AdmiralCommand (world.command) and map tools through CommandOverlay. Hangar (scripts/ui/hangar.gd) is the pilot's B panel: its frame (title, status, Launch and Close, tab buttons, scroll area, gear-slot row) is the scene scenes/ui/hangar.tscn, and the script makes the 6 gear-slot cards, decides where the pilot is (mode(), can_shop()), switches tabs, refreshes 4 times a second, and has the card helpers (_card_width, _grid, _make_card). Its parts: HangarLaunch (status line, Launch button, hyperspace-launch row, launch() and launch_at()), HangarShips (hull cards with trade-in prices), HangarModules (module cards and the note line, buying/selling at the mothership or inside a repair bay), HangarGear (gear cards plus the gear-slot row and selling) and HangarKits (the repair kit card). The libraries are static: they keep no state and read the owner panel's fields directly. The HUD (HudPanels, HudInput) and tests/ui_tour.gd still use only the shells' public face: setup(), _set_tab(), tab, launch(), mode(), and the closed / tool_armed signals.

### Starting up: main, autoloads, sound, camera

The "shell" is the outer layer that starts the game and connects everything else. main.gd is the script of the main scene (scenes/main.tscn). It runs right after the two autoloads. It applies a few launch options: --seed seeds the shared random sequence, plus --speed and --snap. Then it shows the start screen, or two fallback buttons if that scene is missing, or starts at once in test and windowless runs. start(role) builds the World, adds the HUD and the Sfx sound player when there is a window (neither with --sim-only, the speed mode of windowless test runs, see "Speed-ups" below), loads a tests/<name>.gd script for --test, auto-launches the human in --auto runs, and prints the "match:" line. main.gd has two parts. MainReport (main_report.gd) counts tick costs, prints the per-minute report and prints the end-of-match SUMMARY JSON; test tools read these lines, so their text never changes. MainDebugOverlay (main_debug_overlay.gd) is the plain text overlay and F1 key used only when the HUD scene is missing. Two autoloads (scripts that Godot starts first and every file can reach by name) sit beside it. Game (autoload/game.gd) reads the command-line options after `--` into Game.opt(), builds the rule variants (Rules.VARIANT_DEFAULTS changed by --variant) into Game.variant(), and holds Game.world. It asks GameInputMap (autoload/game_input_map.gd) to define every key and mouse control. Events (autoload/events.gd) is the signal bus, a notice board: the simulation posts signals there, and the HUD, Sfx, main.gd and tests listen, so headless runs play the same match. Sfx (audio/sfx.gd) listens to Events.cue and plays sounds only when the player would hear them: on screen, not in the fog, louder near the centre, rate-limited, with 14 voices taking turns. It builds all its sounds at startup with the static synthesizer SfxSynth (audio/sfx_synth.gd), which makes tones, filtered hiss and loudness envelopes and packs them into 16-bit WAV samples. CameraRig (camera/camera_rig.gd) is the Camera2D node in the world scene. It has a follow mode for pilots (look-ahead, edge peek, a zoom-out limit set by ship size) and a free mode for admirals and spectators (wheel, move keys, screen edges, middle-drag, minimap jumps). WorldSetup sets it up; the minimap, the admiral board, HudInput, the command overlay, Sfx and tests use it.

### The tests

The tests/ folder holds the game's test and measurement scripts. None of them is part of normal play. Each one is a plain Node script with a setup(world) function. When you start Godot with --test=<name>, main.gd loads tests/<name>.gd after it has built the World, adds the script to the scene after the World, and calls setup(). From then on Godot calls the test's _physics_process() (or _process() for the windowed ones) every tick, and the test quits the program when it is done. They fall into four families. (1) Pass/fail checks that print PASS/FAIL lines and end with "<name>: N failures": load_all (every script and scene still loads), bot_pilot (presses the real keys to fly the human's ship: thrust, strafe, shield focus, energy routing, repair kit, docking) and support_probe (repair bays, bay drones, the lockout after a hull hit, Bay Defenses, repair kits, wards, drone rebuilds). The ui_tour script clicks through the HUD headless with --force-hud, or takes screenshots when it has a window. (2) The behaviour fingerprint det_hash, which prints a hash of the whole game state every 5 game seconds (and, once at the end, the next number of the shared random sequence as "DET_RNG"). Refactors are compared against it line by line (docs/CODE_STYLE.md Part 3). (3) Scenario tests that set up a special situation by hand: arena (two small squads of AI pilots dogfight in open space), ms_duel (scripted attackers, flown by its own small Siege controller, besiege the mothership in scenarios A-I) and endgame (starts at 25:00 fully teched to test the C11 retreat variants). endgame, det_hash --late, pilot_audit --late and admiral_audit --late get that late-game setup from LateGame (tests/lib/late_game.gd). (4) Probes that watch a normal all-AI match and print numbers: match_probe (the big picture every minute), fun_probe (the "fun meter", one FUN_JSON line; see docs/FUN_METRICS.md), perf_probe (turns on World.profiling so main.gd prints each system's cost; --late starts at 25:00, --noprof leaves the profiling off for the cleanest speed number) and pilot_audit (a bug hunt for the AI pilots: counts stuck ships, rock contact, shots into rocks and the causes of death, plus the damage pilots deal and take, how their retreats start and end, ships pressed against a mothership hull and what big ships aim at during a siege, in AUDIT lines every minute and one AUDIT_JSON line at the end that also lists every pilot death and every stuck episode) and admiral_audit (the same for the AI admiral: build plan, drones, turrets, repair bays, the push lane, sieges and why they end, mothership moves, and who kills the admiral's structures, in ADM lines every minute and one AUDIT_JSON line at the end). spectate_shots is a windowed photo tour of the busiest fights. The tests read game state but never change game code. Some set test switches on game objects: PilotAI.hold_point and launched_at, World.profiling, Combat.emit_damage_events (fun_probe and pilot_audit, to receive Events.damage_applied) and Ship.controller.

## Speed-ups you will see in the code

Hundreds of full AI matches run for testing, so some code is shaped for speed. Every speed-up was checked to change nothing at all about what the game does (tests/det_hash.gd compares a fingerprint of the whole game state every 5 seconds). Together they make the simulation about 12% faster.

- AI pilot parts (scripts/ai/pilot_*.gd) look their brain up once per function into a local called `brain`, because each use of the weak link costs a little.
- Vision (scripts/world/vision.gd, vision_rays.gd): viewers standing in the same cell with the same sight share one answer; "explored" cells are marked once per cell + radius; ray directions are worked out once per ray count; the ray cache keeps up to 30,000 answers.
- Shots (scripts/world/projectiles.gd): a shot whose whole straight path is clear of rocks when fired never checks for rocks again (rocks only ever disappear).
- Rock dodging (AsteroidField.clear_at): a map of how far every 100-unit square is from the nearest rock lets units in open space skip the rock search.
- The spatial hash (scripts/core/spatial_hash.gd) remembers which part of each row has units, so wide searches skip empty space.
- Small caches: a gun's turn rate and a minion's round speed are read from the data once, not every tick.
- `--sim-only` (Game.sim_only), a speed mode for windowless test runs: everything that only draws or sounds is switched off (the unit pictures and flame emitters, the shot and effect drawing, the sound cues, the HUD and the camera). A windowless run still paid for all of that, about half of its computer time. The match is exactly the same (det_hash proves it); one detail needs care: Godot's CPUParticles2D takes a number from the shared random sequence when it is made, so ShipVisual takes the same three numbers itself in this mode. Without the option the game is exactly what it was.
- Hull distance (AI pilots steering clear of the motherships): a hull that is clearly too far away is skipped by a cheap distance check, the direction a pilot wants to go is worked out only once a hull is near, and the nose arrow of a mothership's keel is kept until the ship turns (Mothership.keel_arrow()).
- Minion targeting asks "does a rock hide it?" only of an enemy that would become the best target so far.

## How to find things

- Start from World (scripts/world/world.gd): its THE PARTS list names every part and system.
- Every file's header says who uses it; search the project for a class name to see every caller.
- Numbers live in scripts/data/; rules of thumb and their history are in docs/DESIGN.md.
- Something happened (a kill, a turret lost, research done)? Look at scripts/autoload/events.gd: every message on the board, and the HUD and economy listen there.
- To try a new mechanic, add it as a switchable feature (docs/FUN_PLAN.md, section 3), not by editing shared code.

## Words used in the code

- **--fixed-fps 60**: A Godot option that makes every tick exactly 1/60 of a game second, however fast the computer is. Runs repeat exactly and go as fast as the machine allows.
- **4 Hz refresh**: the panel rewrites its texts 4 times a second (every 0.25 s)
- **A* (A-star)**: A path search that always tries next the dot with the smallest 'cost so far + straight-line distance still to go', so it heads straight for the goal.
- **admiral**: The team member who doesn't fly: they spend the treasury and give big orders (human or AdmiralAI).
- **aggro / leash**: Aggro: when a unit hurts an enemy pilot ship, turrets and minions near the victim prefer to shoot that unit for a while; a unit's aggro range is the distance at which it starts a fight. Leash is how far from home it will chase before giving up and resetting.
- **aim point / face point**: Where the guns aim, and where the hull turns. They usually match; holding Ctrl keeps the hull's heading while the guns follow the mouse.
- **alpha**: How see-through a colour is: 0 invisible, 1 solid (Palette.with_alpha).
- **anchor / anchored**: The spot a repair bay or ward flies to. Once it gets there it parks for good, and its state becomes 'anchored'.
- **arc length (s)**: How far along a polyline a point is, measured from its first point in world units.
- **Aurelian / Halcyon**: Team 0, the amber team. Aurelian is its player-facing name (Rules.TEAM_DISPLAY); Halcyon is the internal label kept in the code (Rules.HALCYON, Rules.TEAM_NAMES), the logs, the JSON and the tools.
- **autoload**: A script that Godot starts before everything else and keeps running. Every file can reach it by its name. Here these are Game (options, variants, the running match) and Events (the signal bus).
- **backdoor protection**: Pilots do only x0.3 damage to a turret unless one of their own minions is within 1800 world units of it.
- **base class**: A shared starting script (Unit) that other scripts extend to get its variables and functions for free.
- **big ships**: Frigates and capital ships (size class SIZE_LARGE or bigger).
- **binary heap**: A list arranged like a family tree (entry i's children are at 2i+1 and 2i+2) so that the smallest entry is always at the front and can be taken off quickly.
- **bisect**: Find a crossing point by halving the gap between an 'outside' sample and an 'inside' sample several times (6 times in MothershipHull.hit_t).
- **bitmask**: A whole number whose binary digits work as on/off switches. seen_mask and visible_mask keep one switch per team (bit 1 << team is on once that team has seen the unit). A physics collision layer is a bitmask too: collision_layer = 4 puts a unit on layer 3, the 'structures' layer that pilot ships bump into, and a mask of 0 means the unit never checks for bumps itself.
- **blocker**: a function that returns the reason something can't be done yet, or "" when it can
- **boost / flight assist**: Boost is extra speed that costs energy. Flight assist damps sideways drift when not strafing or boosting.
- **bounty / assist / streak / ace**: A bounty is the pay for destroying something. Pilots who helped kill an enemy ship (at least 10% of the damage in the last 15 s) share an extra assist reward. A streak is kills without dying, and 3 in a row makes an ace (faster and harder-hitting for 25 s).
- **C11 retreat variants**: A design question from docs/DESIGN.md A2: what a badly damaged mothership does. The choices left are systems_failure (the default) and none (used by tests); a third, jump, was tested and taken out. You pick one with --variant=retreat:<choice>.
- **cache**: A lookup table of answers already worked out, so they are not computed twice.
- **callsign**: A pilot's short nickname (Roster).
- **card**: a clickable box (CardButton) with a title, a description and a footer line showing price, status or the reason it can't be bought
- **choke**: A narrow gap (86 world units) at each jungle entrance. Only small ships fit through.
- **chunk (drawing chunk)**: A 4,000-unit square patch of rocks that draws itself. Godot caches the drawing, so only the patch with a destroyed rock redraws.
- **collision layer bitmask**: A number where each bit stands for one physics layer: 1 = layer 1 (rocks), 8 = layer 4 (ore rocks).
- **connector (the Crossing)**: The lane straight down the middle of the map (x = 20000) that joins the top, mid and bottom lanes.
- **controller / ShipControls**: ShipControls is a ship's control form (which way to fly, whether to shoot). Every tick its controller fills it in: the player's keys (PlayerController), an AI brain (PilotAI), or ms_duel's scripted Siege.
- **corridor**: An open band of space around a centre line: one of the three lanes or the connector. 'half' is half its width.
- **counter-rotate**: The Visual node turns itself back against its unit's rotation so bars and text stay upright; shapes are turned by hand.
- **credits**: A pilot's own money, used to buy hulls, modules, gear and repair kits.
- **cuts**: A weapon flag: true means it can damage asteroids (capital-class shells and some ion beams).
- **damage ramp**: Each shot a turret fires at the same ship adds 20% damage, up to +100%.
- **damage table**: Rules.DAMAGE[weapon kind][target size class]: a multiplier on a hit's raw damage (1.0 normal, 0.5 half, 2.0 double, 0 none). It makes each weapon good against some targets and bad against others.
- **decibels (dB)**: The usual loudness scale for sound volume. linear_to_db turns a 0..1 loudness into decibels.
- **defend call**: When at least 2 enemy big ships push near our mothership, every AI pilot nearby is sent to TeamState.defend_point for 12 s, renewed while the push lasts.
- **dim**: a disabled card drawn see-through; it ignores clicks
- **director**: An object that schedules things in the match over time. MinionDirector sends minion waves; JungleDirector respawns jungle camps.
- **drop-off point**: The spot beside a mothership where mining drones unload ore. A drone unloads once it is within 140 of the hull.
- **echo (key)**: The repeated key events sent while a key is held down; the HUD ignores them.
- **edge field**: A one-tick request in ShipControls (special, focus_request, energy_request, use_kit, dock). The ship clears it after reading, so each press acts once.
- **edge peek**: In follow mode, holding the mouse at a screen edge pushes the view a little further that way (up to a quarter of the view).
- **EMP / jam / paint / support aura / ace**: Timed ship effects: emp_t (engines at 35%, no boost), jam_t (enemy vision shrinks near us), paint_t (+30% torpedo damage taken), support_t (+6% turn, +6% damage, +8% reach), ace_t (Rules.ACE_SPEED/ACE_DAMAGE after Rules.ACE_KILLS kills in a row).
- **energy routing**: The EnergyPool mode that trades fire rate, shield regen, thrust, turning and boost cost (Rules.ENERGY_MODES).
- **entropy (hull variety)**: A measure of how evenly something is spread out. fun_probe divides it by its largest possible value, so 1.0 means every hull type was flown equally.
- **envelope**: How a sound's loudness changes over time. Here it is a 12 ms exponential rise, then an exponential fade to silence.
- **escort bonus**: Extra ore money for the pilots who flew near a mining drone during its trip (MiningDrone.escorts, Economy.deliver_ore).
- **facility / research / tier**: Facilities are modules built onto the mothership (Tech.FACILITIES) that unlock ships or research. Research items are upgrades, shown in the board's columns. A tier is the ship size an upgrade targets: small, medium, large or capital.
- **FIXED / TURRET / AUTO mount**: The three ways a WeaponMount can be fitted. FIXED fires along the nose. TURRET swings toward the owner's aim point within its arc. AUTO picks its own targets.
- **flak / flak burst**: Flak rounds burst and hurt everything in a small circle (the 'burst' radius), when they touch a unit or run out of time.
- **fleet power**: One number for a side's pilot-ship strength: size weight 1-4 times (0.4 + 0.6 x hull fraction).
- **flight assist**: Damps sideways drift while not strafing or boosting (f_assist).
- **footer**: the bottom line of a card: price, progress, 'Owned'/'Built'/'Done', or why it is blocked
- **forwarder**: A function with the old name that only calls the part holding the real code, so other files keep working unchanged.
- **forwarding function**: A tiny function left on the original class with the old name, which just calls the real code that now lives in another file. Other files can keep calling the old name.
- **free camera / follow camera**: Free: the camera goes anywhere (admirals, spectators). Follow: it glides after the human's ship (pilots).
- **FUN_JSON**: fun_probe's single output line. It holds every fun number as JSON text; docs/FUN_METRICS.md explains each one.
- **gate / choke**: Two big rocks on a lane wall at a jungle entrance with an 86-unit gap (MapLayout.CHOKE_GAP) between them. Only strike craft fit through.
- **hangar mode**: where the pilot is: dock, dead (respawning), bay, flying, spooling, bay_launch or offline; decides what the hangar allows
- **hash / fingerprint**: One short number made from a long text. If anything in the text changes, the number almost always changes too. det_hash uses it to compare whole game states.
- **headless**: Running Godot with no window (--headless). Tests run faster that way, and nothing is drawn.
- **high-pass filter**: A filter that lets high sounds through and holds back low ones. Sfx uses one at 400 Hz to turn random noise into hiss without rumble.
- **hold_point**: A PilotAI field that tests set to make an AI pilot hold a given spot instead of its lane station.
- **HUD**: Heads-up display: everything drawn on top of the game world during a match.
- **hull**: A ship type a pilot can fly (Scout, Fighter, ...), and also the hit points of its body. At 0 hull the unit is destroyed.
- **hull fraction / hull_dist**: How much hull is left (0..1), and the distance from a point to the mothership's hull surface.
- **hyperspace launch / spool**: with the Hyperspace Module, a docked pilot's jump drive charges for World.HYPERSPACE_SPOOL seconds, then the ship appears at a chosen repair bay
- **inner / middle node**: An inner ore node sits near one team's mothership, and only that team may build PD or torpedo turrets there. A middle node takes PD turrets from either team.
- **input action**: A named control such as "fire" that one or more keys or mouse buttons can trigger. Code asks Input.is_action_pressed("fire") instead of asking about one key.
- **jungle / jungler / derelict**: The jungle is the rocky space between lanes. Derelicts are neutral monster ships living there. A jungler is a pilot who hunts them.
- **keel / capsule**: The mothership's hull is a capsule: a thick line with round ends. The keel is the line down its middle. Distances to the hull are measured from the keel, minus half the hull's width.
- **keep-out circle**: A circle that new rocks must not overlap: around nodes, camps and bases.
- **kill_silently**: Combat.kill_silently(): removes a unit with no reward, no news and no on_killed(). Used for expired kit drones, snubs that have landed, and drones whose owner is gone.
- **lambda**: A small function written in place, for example inside connect(...) or in ui_tour's step lists.
- **lead point**: Where a moving target will be when a round reaches it (Util.lead_point); a ship whose first gun is a beam aims all its turrets straight at the target, with no lead (so the battlecruiser's heavy cannon fires without lead).
- **lead shot**: Aiming at where a moving target will be when the round gets there, instead of where it is now (Util.lead_point).
- **leash**: How far a minion or derelict will chase away from its lane or home before it gives up on a target.
- **lerp**: Linear interpolation: mixing two values (such as colours) in a straight line by a 0..1 amount. Moving part of the way each frame with 1 - exp(-k*dt) as the amount makes the slide equally smooth at any frame rate (a bigger k means faster).
- **lit / explored**: Lit = seen right now; explored = seen at least once (drawn less dark).
- **lockout**: A repair bay stops repairing for 5 s after its hull is hit.
- **map tool / arm**: the Admiral picks a tool (bay, ward, waypoint, move, fleet_move, fleet_hold) on CommandOverlay; the next map click uses it
- **metadata**: A named value that Godot lets code store on any node (get_meta/set_meta). MiningDrone uses 'idle_t' this way.
- **minimum spanning tree**: The shortest set of straight links that joins a group of points together. The jungle uses one per quarter (made with Prim's method), plus one extra link to make a loop.
- **mining drone / drone line**: Small robot ships that mine ore at a node and bring it home; 60% of the ore goes to the treasury and 40% to the team's pilots. The drone line is all our drones, including the ones queued for building.
- **minion / wave / Fleet Command**: Minions are small computer-flown lane ships. They leave each mothership in groups (waves) and push down the lanes. The Fleet Command Module stops the free waves and lets the admiral buy minions (at most 30) and give them orders.
- **mirror**: Flip a point left-to-right across the map's centre line (x becomes W - x; MapLayout.mirror). Aurelian's half of the map is made first and then mirrored for Cinder, so both sides are equal.
- **modulate.a**: How solid a node is drawn: 1 = solid, 0 = invisible; used to fade lines out.
- **mount (fixed / turret / auto)**: A gun's place on a hull. Fixed fires along the nose, turret follows the pilot's aim inside its arc, auto picks its own targets.
- **ms/sim-s**: Milliseconds of computer time spent per second of match time (60 ticks). Used in the minute report and the --profile line.
- **multiplier**: A number you multiply by: x1.0 changes nothing, x0.3 leaves 30%, x1.25 adds 25%.
- **named look (type variation)**: A named style in the game's theme (for example MistText or HangarLook) that a scene node picks with its theme_type_variation. UiKit.make_theme() makes them from Palette, so scene files never hold colours.
- **Newtonian-lite**: The flight model from v1: ships keep drifting until thrust changes it, with a soft speed cap, turn bleed and flight assist to keep it easy.
- **orthogonal**: v.orthogonal() is the arrow at a right angle to v, pointing straight sideways. Minions and snub fighters use it to circle a target.
- **override**: A script that extends Unit writes its own function with the same name, and that version runs instead.
- **paint**: A mark that support corvettes put on enemy ships within 1800 units for 1.5 s (Ship.paint_t). Torpedoes do extra damage to painted ships (Combat.PAINT_BONUS).
- **painted**: Marked by an enemy Support ship (Ship.paint_t above 0): torpedoes do 30% more to it.
- **part (part object)**: A small helper object that does one job for a bigger class (its owner), such as TeamTech for TeamState or VisionRays for Vision. The owner makes it once, keeps it, and forwards calls to it.
- **PASS / FAIL lines**: One printed line per check in bot_pilot and support_probe. The last line, '<name>: N failures', is the verdict (0 = all good).
- **PD (point defense)**: Fast, weak guns that shoot down torpedoes and small craft.
- **PD turret / torp turret**: Point-defence turret (fast gun, good against small craft) and torpedo turret (homing torpedoes against big ships; needs Platform Missiles research and fits only at inner nodes).
- **physical key code**: A key identified by its place on the keyboard (named after a US layout), so W/A/S/D stays in the same spot on other keyboard layouts.
- **pilot-seconds**: fun_probe's time unit: one pilot for one second counts as 1. It is summed over all AI pilots.
- **PLAN / LOOKAHEAD**: The AI's fixed build order, and how many unfinished steps it may look past a blocked one (4), so the order mostly holds.
- **point defense (PD)**: Small automatic guns that shoot strike craft and enemy torpedoes.
- **polyline / segment / s**: A path of straight pieces (segments) joining a list of points in order; lanes are stored this way. s (the arc length) is how far along the path a place is, in world units, counted from our end.
- **pooling / free list**: A gone round's slot number is kept on a list and reused by the next spawn, instead of making and throwing away objects.
- **PRNG / Mulberry**: A pseudo-random number generator: it makes numbers that look random but are worked out by a fixed recipe. Mulberry uses the 'mulberry32' recipe. The map uses seed MapLayout.SEED, rock shapes use SEED+77, and the stars use 99.
- **profiling / ms per sim-second**: World.profiling times each part of the game's work. main.gd prints how many milliseconds of real time each part costs per second of game time.
- **push lane / front**: The lane where our minions are furthest ahead, and how far along it (0..1) the furthest one is.
- **px**: How many world units one screen pixel covers at the current zoom (1 / zoom). Line widths and text sizes are multiplied by it, so they keep the same size on screen.
- **quadrant (tl, bl, tr, br)**: The four quarters of the jungle: top-left, bottom-left, top-right and bottom-right. Only tl and bl are authored; tr and br are mirror copies.
- **queue_free**: Godot's way to delete a node at the end of the current frame
- **radian**: An angle unit. A full turn is about 6.28 radians (TAU); one radian is about 57 degrees.
- **radians**: Angle unit; a full turn is TAU (about 6.28), one radian is about 57 degrees.
- **ray casting**: Sending straight lines out from a viewer to find which cells it can see, stopping at rocks.
- **reference cycle**: Two RefCounted objects holding each other, so neither is ever freed (a leak).
- **repair bay**: A structure that flies out, anchors for good, and sends drones to heal nearby friendly ships.
- **research**: A tech-tree upgrade bought by the admiral. When it finishes, its effect is added to the team's upgrade fields.
- **resist**: The share of each hit that is blocked (0.2 = 20% less damage), capped at 0.75 for ships.
- **resource node / ore**: An ore field: a cluster of ore rocks that mining drones harvest (1 ore delivered is worth 1 credit), with turret slots. Inner nodes sit near one mothership and only that side builds there; middle nodes are on the central crossing and either side may build.
- **respawn strain**: If 4 pilots of a team respawn within 30 s, their mothership's guns slow to 60% and its shield stops refilling for 20 s.
- **reveal (Scout Ping)**: A circle lit for a few seconds that ignores asteroids.
- **RID**: The physics engine's id for a body or shape that was made directly through PhysicsServer2D rather than as a scene node.
- **round**: One bullet, torpedo, shell or flak pellet in flight (one slot in Projectiles).
- **route graph / node / edge**: The road map for AI movement. Nodes are dots and edges are straight links between them, each costing its length.
- **sample / sample rate**: A digital sound is a list of numbers between -1 and 1 called samples. The sample rate is how many there are per second (SfxSynth.RATE = 22050).
- **scene (.tscn)**: A Godot file that holds a tree of nodes and their settings. Every screen's fixed layout lives in scenes/ui/*.tscn; its script reaches the nodes with @onready and fills in what changes while playing.
- **seed (--seed=N)**: The starting number for a random sequence. --seed=N sets it for all the game's random rolls, so the same N plays the same match. (The map layout is fixed: its own Mulberry sequence always starts from the same seed.)
- **shield zone / focus / energy routing**: A pilot ship's shield has front, rear, left and right zones; a hit drains the zone facing it. Focus (arrow keys) moves more of the total shield to one side (Rules.FOCUS_WEIGHTS). Energy routing (keys 1-4) sends more power to weapons, shields or engines.
- **siege (gather / assault)**: A late-game attack on the enemy mothership down one lane. In gather, big ships meet at a staging point; in assault, everyone closes in.
- **signal / emit / connect**: A signal is a named message with a few values attached, such as Events.unit_killed. Code emits (sends) it; any other script can connect a function to it, and Godot then calls that function with those values every time it is sent. For example Events.admiral_result reports each admiral order's outcome, and the HUD shows it as a toast (a short pop-up message).
- **size class**: A number for how big a unit is: 0 small (strike craft, drones), 1 medium (corvettes, monsters), 2 large (frigates), 3 capital, 4 structure (turrets, bays), 5 mothership, 6 torpedo (only a damage-table column). Lists with 4 entries are read small, medium, large, capital.
- **slot**: Two meanings. A turret slot is one of the turret spots around an ore node (ResourceNode.slot_pos / slots). A projectile slot is a round's number in Projectiles: each fact about the round (position, speed, damage...) sits at that number in its own list ("parallel arrays").
- **small only**: A route dot or link that only small ships (strike craft, admiral repair bays and wards) may use. These are the jungle parts of the route graph.
- **spatial hash / big_hash**: A grid that files units by map square (World.unit_hash), so 'who is near here?' checks only a few squares; query() empties and fills a scratch list. big_hash holds only the units wider than 60 world units.
- **spool (hyperspace)**: The 6 s wait (World.HYPERSPACE_SPOOL) before a hyperspace-launched ship appears at a repair bay. The pilot state is 'spooling' during it.
- **staging point**: Where big ships meet during gather: 60% down the lane, but at least 7,000 short of the enemy mothership (TeamState.siege_stage_point).
- **stamp**: A counter that goes up by one for each new search or update, so old marks never need wiping. AsteroidField marks a rock with the current search stamp when it first sees it, so a rock listed in several grid squares is counted only once. Vision lights a cell with the team's update number, and a cell counts as lit only while it holds the latest one.
- **StatBlock / *_pct key**: A bag of named numbers (such as 'income' or 'bounty_pct') that adds up the stats of gear, modules and upgrades. Keys ending in _pct are fractions (0.10 = +10%), and mul() turns a total into a multiplier (1.10).
- **static function / static library**: A function that belongs to the class itself and is called without making an object, e.g. UiKit.label(...) or WorldSetup.build(world, role). A static library is a script of only such functions, with no memory of its own: each function is handed the object it works on (ShipStats, ShipFlight, WeaponMountTargeting).
- **strafe / port / starboard**: Sliding sideways with the side thrusters. Port is the ship's left (A), starboard its right (D).
- **streak / ace**: Kills in a row without dying. At 3 or more the pilot's ship becomes an 'ace' for 25 s (faster and hits harder).
- **SUMMARY line**: The one-line JSON result that main.gd prints at the end of a match ("SUMMARY {...}"). Test tools read it.
- **swept test**: Checking the whole line a round flew along this tick (from where it was to where it is; hit_t), so fast rounds can't skip past a target.
- **systems failure**: The mothership's once-per-match emergency at 35% hull: a 45 s outage (no launches, respawns or shopping there, and its guns fire at half speed).
- **t (along a line)**: A place on a line as a fraction: 0 = the start, 1 = the end.
- **tech / research**: An upgrade from Tech.TECHS, bought with credits and finished after a research time.
- **test harness (--test=<name>)**: main.gd's way of running a test: it loads tests/<name>.gd after building the World, adds it to the scene and calls setup(world).
- **theme**: Godot's set of default looks (boxes, colours, font sizes) for every kind of control. UiKit.make_theme() builds the game's theme from Palette, with its named looks.
- **think**: The AI admiral's once-a-second decision pass inside tick(). Before each think the timers just count down.
- **tick**: One small step of the simulation; World runs 60 per second and calls sim_update(dt) on every living unit.
- **toast**: a short message that pops up on screen (Events.toast)
- **trade-in**: buying a different hull gives back half the old hull's price and 40% of its modules' prices
- **treasury / credits**: Credits are the game's money. Each pilot has their own credits; each team has a shared treasury that the admiral spends on facilities, research, turrets and drones.
- **unit vector**: An arrow of length 1 that only shows a direction (for example Util.port_of).
- **variant**: A switch for a design choice left open in DESIGN.md (Game.variant; defaults in Rules.VARIANT_DEFAULTS, changed with --variant=key:value). Only "retreat" (C11: what a mothership does at 35% hull) is left; the options that lost their tests were taken out of the code.
- **Vector2.INF**: A position at infinity, used to mean 'no drag is happening'.
- **voice**: One AudioStreamPlayer that plays one sound at a time. Sfx has 14 that take turns.
- **ward**: A small drone that anchors and keeps watch so the team can see that spot. 6 per team; placing a 7th removes the oldest.
- **waypoint**: The admiral's rally marker. Friendly ships inside its 1200-unit circle get small speed, shield and vision bonuses for 75 s.
- **weak link (WeakRef)**: A pointer to an object that does not keep it alive. Parts use one to reach their owner, so the owner and its parts can be freed when a match ends (two normal links would keep each other alive forever).
- **widget**: One small, self-contained part of the screen with its own script (e.g. the top bar or the feed).
- **world unit**: The game's distance unit, about one pixel at normal zoom; the map is 40,000 x 26,000. Speeds are world units per second.
- **z_index**: Drawing order for 2D nodes: a higher z_index draws on top.
- **zoom (Camera2D)**: How big things look. At zoom 1 one world unit is one pixel. Visible world width = screen width in pixels / zoom, so a smaller zoom shows more of the map.
